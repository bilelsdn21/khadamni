General Introduction

Project Overview

Khadamni is a real-time, location-based service marketplace web application. It connects Clients who need immediate services with Service Providers who are available nearby. The platform addresses limitations found in existing platforms like Fiverr, Upwork, and InDrive by offering real-time matching, direct negotiation, live location tracking, and a trust system built on mutual ratings.

Problem Statement

⏱

Delayed Matching

Clients post requests and wait hours or days for responses on existing platforms.

👁

No Real-Time Visibility

Clients cannot see which providers are currently available and nearby.

📍

No Proximity Matching

Platforms don't leverage geographic proximity for immediate, real-world service delivery.

💰

Rigid Pricing

Platforms impose fixed pricing models, limiting negotiation between parties.

🗺

No Live Tracking

Once a provider is hired, clients have no visibility into their location or arrival time.

Proposed Solution

  • A map-based interface showing available providers in real-time
  • Instant request and notification system for immediate matching
  • Private chat for direct price/scope negotiation between client and provider
  • Live location tracking during active jobs
  • Mutual rating system to build trust and accountability
  • Flexible payment (cash or card) with fair cancellation policies

Non-Functional Specifications

Performance

  • Map loads within 2 seconds
  • Provider markers render within 1 second of map movement
  • WebSocket message delivery < 500ms latency
  • API response times < 300ms for standard queries
  • Geospatial queries optimized with MongoDB 2dsphere indexes

Security

  • Passwords hashed with bcrypt
  • JWT with short-lived access tokens (15 min)
  • Refresh token rotation on each use
  • Optional TOTP-based two-factor authentication
  • CORS restricted to frontend origin
  • Input validation on all endpoints (Pydantic)
  • Rate limiting on auth endpoints
  • WebSocket connections authenticated via JWT

Privacy

  • No government ID required — verification via email, phone, 2FA
  • Location shared only during active jobs, only with matched party
  • Location tracking stops immediately on job completion/cancellation
  • Provider location is approximate on discovery map

Scalability

  • Stateless backend — horizontally scalable
  • MongoDB indexes for high-read geospatial workloads
  • In-memory ConnectionManager for MVP; Redis pub/sub for multi-server
  • Debounced map queries to reduce backend load

Compatibility

  • Browsers: Chrome, Firefox, Safari, Edge (latest 2 versions)
  • Mobile-first responsive design
  • Requires browser Geolocation API (HTTPS required)

MVP Development Phases

Phase 1 Week 1-2

Foundation

FastAPI project scaffold, MongoDB connection + indexes, auth system (register, login, JWT, refresh, email verification). React project scaffold, routing, AuthContext, Axios interceptors, login/register pages.

Deliverable: User can register, verify email, log in, and see a protected page.
Phase 2 Week 3-4

Provider Profiles + Map

Provider profile CRUD, portfolio upload, availability toggle. Map page with Mapbox: provider markers, category filter, proximity filter, marker popups.

Deliverable: Client sees available providers on map with custom markers, can filter and view profiles.
Phase 3 Week 5-6

Requests + Notifications

Service request state machine, notification WebSocket, ConnectionManager. SendRequestModal, real-time notification toasts, accept/reject UI.

Deliverable: Client sends request, provider gets real-time notification, accepts or rejects.
Phase 4 Week 7

Real-time Chat

Chat WebSocket with room-based broadcasting, message persistence, cursor pagination. ChatPage with typing indicator.

Deliverable: Both users negotiate in real-time chat after request acceptance.
Phase 5 Week 8-9

Live Tracking + Job Completion

Location WebSocket, Haversine distance calculation, dual-confirmation "done" logic. LiveTrackingPage with both markers and distance indicator.

Deliverable: Both users see each other's live location on map. Both can press "done" to complete job.
Phase 6 Week 10

Ratings + Job History

Rating submission, average recalculation, job history queries. RatingForm, RatingsSummary, JobHistoryPage.

Deliverable: Mutual ratings after jobs, profiles show ratings, full job history available.
Phase 7 Week 11-12

Polish + Security

2FA (TOTP), rate limiting, input validation, cancellation policies. Settings page, error boundaries, loading states, mobile responsiveness, payment UI.

Deliverable: Production-ready MVP with 2FA, polished UX, and payment readiness.

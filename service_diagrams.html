Auth Service

The Auth Service manages the full authentication lifecycle. A user has at most one active OTP at a time (0..1) since the old one is deleted before a new one is created. A user can have multiple trusted device tokens (0..*), one per saved device. The EmailClient is called once per registration to deliver the OTP, and once per suspension event to notify the user.

Provider Service

The Provider Service handles geolocation-based search using the MongoDB 2dsphere index, then joins with the users collection to fetch avatars. Nominatim converts text addresses to GPS coordinates, and OSRM computes the real driving route. Chat Service

The Chat Service manages both messaging and price negotiation within the same room. Messages can be regular text, price offers, or system events. All new messages and offer updates are broadcast via WebSocket so both parties see changes instantly. A chat room accumulates unlimited messages (0..*) over the lifetime of the job.

Moderator Service

The Moderator Service is the only service that reads across all collections simultaneously to aggregate platform statistics. Suspension is stored directly on the user document with an optional expiry date — the login check auto-lifts it when the date passes. Reports come pre-analyzed by Groq AI, so the moderator only needs to read the summary and confirm a decision.

Architectural Note — Why a Repository layer?

These diagrams show a three-layer architecture (Controller â†’ Service â†’ Repository) while the actual implementation uses FastAPI router functions and service modules with direct Motor calls. The following arguments justify this modeling decision:

Argument 1 — Logical architecture vs physical implementation

These diagrams represent the intended architectural pattern, not literal Python syntax. C4 Level 4 diagrams model design responsibilities, not class declarations. FastAPI service functions grouped by domain are the repository — the pattern exists, just without explicit class wrappers.

Argument 2 — Motor is the repository (strongest)

MongoDB's Motor driver itself acts as the repository layer. When a service calls db.users.find(...), Motor is the abstraction between the business logic and the raw database. The Repository box represents that abstraction — the team simply chose not to wrap it in an explicit Python class.

Argument 3 — Standard academic modeling convention

UML class diagrams in academic reports model responsibilities, not syntax. A module containing cohesive functions that manage user data is a repository by definition. Python's module system is functionally equivalent to a class with static methods — a language-specific detail, not an architectural difference.

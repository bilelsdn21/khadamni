🗄 Database Design

MongoDB with 9 collections. No rigid schema — documents can have different fields per role. Motor is the async Python driver so database calls don't block the server.

users

{
  _id, email, password (hashed),
  first_name, last_name, role,
  // providers also have:
  bio, service_categories[],
  experience_years, job_type,
  latitude, longitude
}

provider_profiles

{
  _id, user_id (→ users),
  full_name, bio, service_categories[],
  hourly_rate, experience_years,
  is_available, job_type,
  latitude, longitude,
  location: { type:"Point", coordinates:[lng,lat] },
  avg_rating, total_jobs
}

⚡ Has a 2dsphere index on location for geospatial queries

service_requests

{
  _id, client_id, provider_id,
  provider_profile_id,
  client_name, provider_name,
  description, status,
  job_type, created_at, updated_at
}
// status: pending → in_progress
//        → confirmed → completed
//        → rejected / cancelled

chat_rooms

{
  _id, request_id, client_id, provider_id,
  status, agreed_price,
  client_confirmed, provider_confirmed,
  created_at, updated_at
}

chat_messages

{
  _id, room_id, sender_id,
  message, message_type,
  // message_type: text | offer | system
  offer_amount, offer_note, offer_status,
  timestamp, is_read
}

Other Collections

// otp_codes
{ email, code, expires_at }

// device_tokens
{ email, token (UUID), expires_at }

// ratings
{ job_id, rater_id, ratee_id,
  score(1-5), comment }

// reports (AI dispute)
{ request_id, reporter_id,
  reason, ai_analysis, status }

Why MongoDB over SQL?

  • ✅ Flexible schema — clients and providers have different fields in the same collection without ALTER TABLE
  • ✅ Native geospatial — 2dsphere index lets us query providers by geographic proximity natively
  • ✅ Document model fits chat — messages, offers, and metadata live in one document naturally
  • ✅ Motor async driver — plays perfectly with FastAPI's async/await model, no thread blocking

🔐 Authentication

Three-layer security: password hash → OTP email → JWT token. Trusted devices skip OTP to avoid friction on repeat logins. File: backend/app/services/auth_service.py

Login Flow

1
POST /api/auth/login — client sends email + password + device_token
2
Backend finds user by email, calls verify_password() using pbkdf2_sha256 hash
3
If device_token matches DB record → skip OTP, return JWT immediately
4
Otherwise: generate 6-digit OTP, store in otp_codes with 5-min expiry, email it via Gmail SMTP
5
POST /api/auth/verify-otp — client sends email + code. Backend validates, deletes OTP, creates JWT + new device_token
6
Frontend stores JWT in localStorage, attaches it to every request via Axios interceptor

JWT Guard — how protected routes work

Every protected route has current_user: dict = Depends(get_current_user). FastAPI calls this function automatically before the route handler runs.

# backend/app/dependencies.py
async def get_current_user(token = Depends(oauth2_scheme)):
    payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    user_id = payload.get("sub")
    user = await db.users.find_one({"_id": ObjectId(user_id)})
    return user  # injected into route handler

Frontend — AuthContext

On every app load, calls GET /api/auth/me to get fresh user data (not stale localStorage). This also refreshes the provider profile so remote/in-place logic is always correct.

# frontend/src/context/AuthContext.jsx
useEffect(() => {
  const token = localStorage.getItem('access_token');
  if (!token) { dispatch({ type: 'LOADED' }); return; }
  api.get('/auth/me')
    .then(res => dispatch({ type: 'LOGIN', payload: res.data }))
    .catch(() => { /* use cached user or clear token */ });
}, []);

Geospatial Index

On startup, database.py creates a 2dsphere index on provider_profiles.location. This lets MongoDB run efficient radius queries like "find all providers within 10km of this point" using the GeoJSON Point format.

# The location field stored in provider_profiles:
location: {
  type: "Point",
  coordinates: [10.1815, 36.8065]  # [longitude, latitude]
}

⚠️ MongoDB stores [longitude, latitude] — opposite of Leaflet which uses [latitude, longitude]. Easy interview trap!

💬 Chat & WebSocket

Real-time bidirectional communication using native WebSockets. One WS connection per chat room. The same WS also carries location pings and job-completion events. File: backend/app/routers/chat.py + websockets/manager.py

ConnectionManager — How rooms work

The ConnectionManager is a Python class with a dictionary: { request_id: [websocket1, websocket2] }. When a message arrives from one socket, broadcast() sends it to all sockets in the same room.

class ConnectionManager:
    def __init__(self):
        self.active_connections: dict[str, list[WebSocket]] = {}

    async def broadcast(self, request_id, message):
        for conn in self.active_connections.get(request_id, []):
            await conn.send_json(message)

⭐ Ratings

Both parties rate each other after completion. Provider's avg_rating and total_jobs update automatically. File: backend/app/services/rating_service.py

How avg_rating updates

When a rating is submitted, the backend uses MongoDB's $inc and $set to recalculate the running average on the provider_profiles document. No need to re-query all ratings — it's maintained incrementally.

UI Trigger (ChatPage)

When isCompleted && !hasRated → show 5-star rating card. On submit → POST /api/ratings/. On load (if already completed) → GET /api/ratings/job/{id} to check if current user already rated → set hasRated = true to skip card.

🤖 AI Features

Three features powered by Groq (Llama 3.3 70B) + one using pure MongoDB. Files: backend/app/services/ai_service.py + routers/ai.py

1. Client — AI Search

Client types in Tunisian dialect → Groq understands → returns category, urgency, French description, price estimate, key points.

POST /api/ai/analyze-request

2. Provider — Price Stats

When offer panel opens → MongoDB aggregate on real agreed_price values from past completed jobs. Shows range + average. No AI — real data.

GET /api/ai/price-stats/{category}

3. Moderator — Dispute

User clicks Report → fills reason → Groq reads full chat history → returns timeline, evidence for each side, recommendation, confidence score.

POST /api/ai/report

AI Search + Provider Recommendations

After the AI call resolves, the frontend fetches providers for the detected category and ranks them using a score:

// In-place providers — distance matters
distScore  = max(0, 1 - distance / 20000)   // 20km = max range
qualScore  = (avg_rating / 5) * 0.7 + min(total_jobs / 50, 1) * 0.3
finalScore = distScore * 0.6 + qualScore * 0.4

// Remote providers — no distance, pure quality
finalScore = qualScore

Top 3 in-place + top 3 remote shown as clickable cards. Tapping one opens the request modal pre-filled with the AI-generated description.

Why Groq instead of OpenAI / Gemini?

  • ✅ Completely free tier — 14,400 requests/day, no credit card
  • ✅ Fastest inference available — Llama 3.3 70B in ~0.5s
  • ✅ Handles Tunisian dialect well — multilingual model trained on Arabic + French
  • ❌ Gemini: free tier quota was 0 for our project type
  • ❌ OpenAI: paid only

⚛️ React Architecture

The app uses two global contexts, protected routes, and the Axios interceptor pattern. No Redux — Context API is enough for this scale.

AuthContext

Stores user object and token. On mount: calls /auth/me to get fresh data. login() saves token to localStorage. logout() clears everything. Any component calls useAuth().

ThemeContext

Stores theme ("dark" | "light"). On change: sets data-theme attribute on <html>. CSS targets [data-theme="light"] selectors to override colors. Persisted in localStorage.

Axios Interceptor

Every API call automatically gets the JWT token attached — no need to add it manually in every component.

# frontend/src/api/axios.js
const api = axios.create({ baseURL: 'http://localhost:8000/api' });
api.interceptors.request.use(config => {
  const token = localStorage.getItem('access_token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

ProtectedRoute

Wraps routes that require login. If user is null and auth has loaded → redirect to /login. Used in App.jsx for /map, /chat/:id, /tracking/:id, etc.

📡 Real-Time Tracking

Taxi-style GPS tracking after request acceptance. Uses the same WebSocket channel as chat — no extra infrastructure needed. File: frontend/src/pages/TrackingPage.jsx

Provider side

  • 📡 navigator.geolocation.watchPosition fires on GPS change
  • ⏱ Throttled to 1 send per 3 seconds
  • 💓 Heartbeat every 4s resends last position (for static GPS in dev tools)
  • 📤 Sends {type:"provider_location", lat, lng, provider_name} via WS

Client side

  • 📍 Reads stored location from localStorage.client_location
  • 📤 Sends {type:"client_location", lat, lng} once on connect
  • 📡 Receives provider_location → updates provider marker on map
  • 🔔 When distance < 500m → proximity banner appears

Route Drawing (OSRM)

When both positions are known → GET /api/providers/route?slat=&slng=&elat=&elng=. Backend proxies to OSRM public API, returns GeoJSON polyline coordinates. Frontend draws a green <Polyline> on the Leaflet map. Re-fetches when provider moves >50m.

Haversine Distance

Used to calculate straight-line distance between two GPS points in metres. Used for: proximity notification (<500m), AI provider ranking (distance score), and live distance chip on tracking page.

function haversine(lat1, lng1, lat2, lng2) {
  const R = 6371000; // Earth radius in metres
  const toRad = d => d * Math.PI / 180;
  const dLat = toRad(lat2 - lat1), dLng = toRad(lng2 - lng1);
  const a = Math.sin(dLat/2)**2
            + Math.cos(toRad(lat1)) * Math.cos(toRad(lat2))
            * Math.sin(dLng/2)**2;
  return R * 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1-a));
}

🎨 Theme System

Dark/light mode without any library. Pure CSS attribute selectors + React context. Files: ThemeContext.jsx + index.css

ThemeContext sets document.documentElement.setAttribute('data-theme', theme). CSS then targets [data-theme="light"] to override every color.

/* Key insight: word-boundary selector [class~=] vs substring [class*=] */
[data-theme="light"] [class~="text-white"]    { color: #1E293B !important; }
[data-theme="light"] [class~="bg-[#22C55E]"][class~="text-white"] {
  color: #ffffff !important; /* restore white text on green buttons */
}

⚠️ Critical: [class~=] matches whole class names only. [class*=] matches substrings — it would accidentally match hover:bg-[#22C55E] and break hover states (like the burger menu). This caused a real bug we fixed.

🛡 Security

Password Storage

Passwords hashed with pbkdf2_sha256 (passlib). Never stored in plain text. Never returned in API responses.

JWT Tokens

HS256 signed. Contain only user_id (sub claim). Expire in 30 minutes (or 30 days with "remember me").

OTP

6-digit random number. Stored in DB with 5-minute TTL. Deleted immediately after use. Prevents replay attacks.

Authorization Checks

Every service function checks that the requesting user is actually the client or provider of that specific request — not just any logged-in user.

Disposable Email Block

Registration checks email domain against a list of known disposable email providers. Prevents fake accounts.

CORS

FastAPI CORS middleware only allows localhost:5173 (frontend). In production this would be the real domain.

❓ Interview Q&A

Common technical questions about this project — with honest, direct answers.

Architecture & Choices

Q: Why FastAPI instead of Django or Node.js?
FastAPI is async-native which is critical for WebSockets and DB I/O. It auto-generates docs. Python is better for AI integration than Node. Django is synchronous and heavier — not ideal for real-time features.
Q: Why MongoDB instead of PostgreSQL?
Providers and clients have different fields — MongoDB's flexible schema avoids complex joins. The 2dsphere geospatial index makes proximity queries trivial. For a chat app, document model fits message storage naturally.
Q: Why WebSockets instead of polling or Server-Sent Events?
WebSockets are bidirectional — both client and provider can send messages. SSE is server-only. Polling wastes bandwidth (we had a polling fallback initially, then replaced it). WS is the right tool for chat.
Q: How does the app handle JWT token expiry?
The token expires in 30 minutes by default. The frontend doesn't refresh it automatically — if a request fails with 401, the user is redirected to login. "Remember me" extends the token to 30 days.

Real-Time & WebSocket

Q: What happens if the WebSocket disconnects?
The ws.onclose handler sets isConnected = false which shows a "Disconnected" indicator. The user can refresh to reconnect. We don't implement auto-reconnect in this version.
Q: How does the ConnectionManager handle multiple tabs?
Each tab opens its own WebSocket which gets added to the same room array. broadcast() sends to all of them. The limit is 10 connections per room (set in chat.py).
Q: Why is the WS authenticated via URL token (?token=) and not headers?
The WebSocket API in browsers doesn't support custom headers during the handshake. Passing the JWT as a query parameter is the standard workaround. The backend validates it immediately on connection and closes if invalid.

Security

Q: Is the JWT token safe in localStorage?
It's vulnerable to XSS attacks. HttpOnly cookies are safer. For this project localStorage is acceptable since there's no rich text input where scripts could be injected. In production we'd switch to secure HttpOnly cookies.
Q: What stops a client from calling /api/chat/{id}/confirm on someone else's request?
Every service function checks str(request["client_id"]) == user_id before acting. If the user isn't a party to that request, they get a 403 Forbidden. The JWT ensures we know who the user is.

AI Features

Q: How does the AI handle Tunisian dialect?
Llama 3.3 70B is a multilingual model trained on Arabic and French data. Tunisian is a mix of both plus Berber words. The model understands the intent even with mixed languages. We tested with "3andi biba mtaa9a" → correctly returned Plumbing.
Q: Why not use AI for price suggestions too?
AI doesn't know Tunisian market rates. A plumber in Tunis costs very differently from a plumber in Paris. So instead we aggregate real agreed_price values from completed jobs on our own platform — actual local market data that gets more accurate as the platform grows.
Q: What if the AI returns invalid JSON?
We use response_format: { type: "json_object" } in the Groq API call which forces valid JSON output. We also have a _strip_fences() function that removes markdown code fences if Groq adds them.

Database

Q: What is a 2dsphere index and why do you need it?
It's a MongoDB index for geospatial data stored as GeoJSON. It lets MongoDB run queries like "find all providers within 10km of this point" efficiently. Without it, MongoDB would have to calculate distances for every single provider document — very slow.
Q: Why do you store [longitude, latitude] instead of [latitude, longitude]?
GeoJSON standard uses [longitude, latitude] order. MongoDB follows GeoJSON. Leaflet uses [latitude, longitude]. So we always have to swap when passing coordinates between the map and the database — a common source of bugs.
Q: How does Motor differ from PyMongo?
Motor is the async version of PyMongo. Regular PyMongo blocks the thread during DB operations. Motor uses async/await so FastAPI can handle other requests while waiting for MongoDB — essential for a real-time app.

Frontend

Q: Why use Context API instead of Redux?
Redux adds complexity (actions, reducers, store). For two pieces of global state (user + theme), Context API is sufficient. Redux becomes worth it when you have many unrelated pieces of state across many components.
Q: What is the Axios interceptor doing?
It's middleware that runs before every request. It reads the JWT from localStorage and adds it as an Authorization header. Without it, we'd have to manually add the token to every single API call in every component.
Q: How does the theme system work without a CSS library?
ThemeContext sets data-theme="light" on the html element. CSS uses [data-theme="light"] [class~="text-white"] to override Tailwind classes. The ~= selector matches whole class names only — critical to avoid matching hover variants.
